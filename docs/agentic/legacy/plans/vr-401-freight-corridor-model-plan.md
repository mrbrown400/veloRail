## decision

Reuse the VR-001 transit proposal dataset as the freight corridor model instead of introducing a parallel registry. Freight corridors remain custom VeloRail overlay data with GeoJSON LineString geometry converted to Google Maps Polyline inputs by existing adapters.

## scope

Tighten proposal freight metadata types and validation, require provenance plus freight owner/operator/usage/electrification fields for freight corridor records, add conversion scenario metadata for converted_passenger concepts, update the Alameda Corridor example, and document source assumptions without changing operational TRANSIT_LINES routing.
